# C2: make the transcode path fit its budget (core, Windows first)

Read `AGENTS.md` first. Owned paths: see `[C2]` in `docs/ownership.toml`.

## Why (measured, `TASKS.md` §C2)
Budget for a non-prefetched 24 MP JPEG → 2560×1440 box: **≤150 ms**.
Measured in release on this machine (6000×4000 q92 → 2160×1440):

| step | time |
|---|---|
| decode | 411 ms |
| resize | 86 ms (CatmullRom) |
| encode | 170 ms |
| total | 681 ms |

In the app, the full image lands about 0.9 s after its thumbnail. The
transcode path is the main thing users wait on.

## Approach (measure each step and keep what wins)
1. **Windows: decode JPEG with WIC using DCT-domain scaling.**
   - `IWICBitmapSourceTransform::CopyPixels` with a scaled size: the
     decoder reduces by 1/2, 1/4 or 1/8 while decoding. Pick the smallest
     scale whose size is ≥ target, then finish with `resize::resize`.
   - Apply the EXIF orientation with `orient::read`/`apply`. Check whether
     `IWICBitmapSourceTransform` can also rotate (`DoesSupportTransform`).
     Either way it must be applied exactly once; the existing orientation
     tests must stay green.
   - ICC: take the frame's color context bytes and call `color::to_srgb`,
     as `decode/heic_wic.rs` does. Reuse its COM guard pattern; that file's
     drop-order and SAFETY rules apply here too.
2. **Encode with WIC's JPEG encoder** (`GUID_ContainerFormatJpeg`,
   `ImageQuality` property) when it beats `image`'s encoder. Measure both.
3. Keep the pure-Rust path for non-Windows (Docker, M2). Only if it is
   cheap, try whether `image`'s jpeg decoder exposes any scaling (zune-jpeg
   does not, as far as known). Do not add dependencies; if a crate would
   clearly win (e.g. `jpeg-encoder`), report the measured case instead.
4. Wire it in `std_formats.rs` / `pipeline.rs`:
   - JPEG on Windows → the WIC path.
   - A WIC failure (exotic JPEG such as arithmetic coding or 12-bit) falls
     back to the `image` path. Never surface a WIC error if `image` can
     decode the file.

## Acceptance
- `core/tests/pipeline_bench.rs` shows the new split. Report it in release
  as decode / resize / encode / total for the same 24 MP file, and also for
  a 12 MP file.
- Target ≤150 ms total for 24 MP. If it is not reached, report the best
  number and what is left.
- Existing pipeline, orientation, ICC and limits tests stay green. Add
  WIC-path tests:
  - orientation 1–8;
  - a CMYK JPEG, or any file WIC rejects, falls back;
  - a truncated file → `Corrupt`.
- `powershell -File scripts/check.ps1 -Rust` and
  `node scripts/gates.mjs --ownership C2 main` pass. Every `unsafe` block
  has a `// SAFETY:` comment.

## Not in scope
Prefetch policy, the passthrough rule (contract), and non-Windows
performance (later).
